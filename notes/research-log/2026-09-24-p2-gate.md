# P2 run — role-aware HIF and the shared contracts, from research to gate

Project folder: [projects/p2-role-aware-hif/](../../projects/p2-role-aware-hif/). Programme:
[projects/PLAN.md](../../projects/PLAN.md). This log records the run and the base update that
PLAN §1 requires before a project counts as done. It covers 2026-09-23 to 2026-09-24.

## Brief

P2 is the programme's first capability project (phase 0). The goals: a `roles` convention on HIF
incidence attributes, a validator with a malformed-case list, role-preserving loaders for XGI and
HyperNetX, and the shared contracts every later project consumes. These are C1 (record format), C2
(store interface), C3 (candidate queue and linter log) and C5 (scorers). The gate (PLAN §4) has
three clauses:

- **G1:** a record round-trips repo format → HIF → XGI and HyperNetX → back with roles intact;
- **G2:** the validator rejects each malformed case in its list;
- **G3:** a smoke test runs one record through queue, structural lint, store and export.

## What was found

Established by the research and the gate. The evidence is in reports 02 and 03 and in
`tests/evidence/library-hif-evidence.json`.

- **HIF is one repository, not several standards.** `pszufe/HIF_validators`, `pszufe/HIF-standard`
  and `HIF-org/HIF-standard` are one repository, renamed and then transferred (HEAD `b691a3d`,
  2026-03-19). It holds two schema files, `hif_schema.json` (`latest`) and `hif_schema_v0.1.0.json`
  (`0.1.0`). Their validation rules have been identical since 2024-10-03. The 404 `$id` is a stale
  path from a same-day rename on 2025-05-02.
- **HIF's version labels conflict.** The CHANGELOG says `v0.0`, a schema file `0.1.0`, the Zenodo
  releases v0.1.0–v0.1.2, and the maintainers "v1". A v2 (temporal, columnar) is planned. Data
  files carry no version marker, and one can live only in `metadata`.
- **Roles fit HIF today only in `attrs`.** The paper's own example of an incidence attribute is
  `{"role": "PI"}`. As far as GitHub search shows, no one upstream has proposed a role convention or
  a data-file version marker.
- **XGI 0.10.2's own HIF functions drop every incidence attribute and every weight.** Roles are lost.
- **HyperNetX 2.4.3 keeps roles as cell properties, but its HIF functions are fragile.** They drop
  the second record of a repeated (edge, node) pair and all metadata but `name`. They fetch the
  schema over the network on every call, return `None` instead of raising, and cannot re-read their
  own directed output.
- **Loaders that build the library objects through public constructors round-trip roles exactly.**
  They work offline and deterministically, including for a node that is both tail and head of one
  fact.
- **P2's design choice: `role-convention` 1.0.0.** The role goes in `attrs.role`, with one incidence
  record per role binding (repeated pairs allowed), `attrs.role-position` for ordered fillers, and
  `metadata["role-convention"]`. No schema change is needed. The repository's own files add the
  `khg-hif/1.0.0` profile and pin the schema by commit URL and sha256.
