### Decisions

1. **The prologue.** The schema line runs verbatim in the `S` fixture of `conftest.py`, in a working directory that
   holds the packaged files under the names the sequences use (`p2-gate.relation-schema.json`, `corpus.khg.jsonl`,
   `qset.c4.jsonl`). Each module imports only the names it uses, so no import is unused; `test_verbatim.py`
   executes the two import lines as written and checks what they bind.
2. **P7's `entities` holds facts too.** The sequence puts `entities` into a fresh store and then `new`; for
   `put(new)` to collide, the store must already believe something on the key. So `entities` is what P7's memory
   holds when `new` arrives: the fixture's entities and the facts P7 believes. The sequence runs twice:
   - **dispute:** Warszawa (and both reigns) stored, Kraków arrives; both birth facts end `disputed` under `m:dis-7`;
   - **close_older:** Louis XIII's open reign stored, Louis XIV's reign arrives; shape `succession`.
3. **P7's `close_older` branch stops early (a finding for the review, no change).** §2.5's table says
   `close_older` is "`end_validity` on the stored fact …, then the put (S-KEY-007)". The §1.3 sequence has no second
   `put`, so run verbatim it leaves the newcomer unwritten, and `current` and `prompt` are empty. The test asserts
   that, then takes §2.5's step: the put succeeds with the L008 warning and the key read finds `f:king-14`. A
   `ms.put(new, actor="p7")` after the `end_validity` call would make the sequence match §2.5.
4. **The collision info is read from the loop variables.** Python unbinds `e` after the `except` block, and the
   block is verbatim, so the P7 helper returns its locals and the test reads `coll`, the one collision.
5. **P3a's mapper uses the fixture's ids** in place of Q-ids and derives the subject from the statement id
   (`<subject>$<uuid>`). It maps P248's item to `source.doc_id` and every snak into `reference` (§2.6, §2.8). A P3a
   reader maps Q-ids to its own ids; the mapper stands in for that.
6. **P3b's model** gives the target and one other candidate the top score, so the pessimistic convention of the
   `hype` preset shows (rank 2 on 10 of the 12 queries) and the numbers follow by hand.
7. **Long lines.** Three verbatim lines exceed 120 columns, as they do in DESIGN.md (ruff E501; line length is not
   checked in CI). `ruff --select F,E9` is clean on `src/` and `tests/`.

### Change to an earlier step (W11b)

- **The defect.** `completion.build_queries` gave a fact-valued target a candidate universe of "the facts of the
  relations its usage admits" among the facts passed in. P3b passes the test split. The manifest puts `f:claim-1` in
  test and the fact it claims, `f:born-louis14-paris`, in train. So the query's universe lacked its own target, and
  any model that ranks the universe fails in `rank_stats` ("the target must be a scored candidate").
- **The fix.** In `src/khg_contracts/scorers/completion.py` the universe of a fact target now also holds the
  target; its docstring says so. Entity and literal universes always held their target, because it is seen in the
  query's own fact.
- **Checks.** W11b's tests pass unchanged: with all fixture records the target was already in the list.
  `test_p3b_a_fact_target_is_in_its_own_universe` and the P3b sequence fail without the fix and pass with it.
- No other file of an earlier step was changed.

### The v1 scope filter (for the review; no change)

§1.3 says "a v1 name that no sequence or gate clause calls is a scope error". Read literally against the §1.3 block
and `tests/gate/`, 26 names of §10.2 are called by neither. §12.1 names most of them as v1 scope for a consumer, so
the two statements disagree on these names:

| Names | Where §12.1 or another section places them |
|---|---|
| `project.rdf_relation_instance`, `from_rdf_relation_instance`, `incidence_rows`, `from_incidence_rows`; `store.StoreBase`, `SystemClock` | P1 (§12.1; §6.3) |
| `project.position_map`, `hyper_relational`, `role_value_set` | P3b (§12.1) |
| `record.derive`, `valid_time`, `value_identity`, `window` | P3a and P1: literals, windows, `derived.valid_time` (§12.1, §2.6) |
| `memory.derive_memory_gold` | P7 (§12.1) |
| `Queue.open`, `reject`, `flag`, `verdict`, `withdraw` | P9: "C3 with verdicts and replay" (§12.1) |
| `migrate.v0_sample_to_v1`; `loaders.khg_to_xgi`, `xgi_to_khg`, `khg_to_hnx`, `hnx_to_khg` | P2: `khg-migrate` and the G1 chain on the migrated sample (§11.3, `tests/migrate/`) |
| `record.resolve_redirects`, `supported_values` | the scorers (§9.1) and evidence reading (§2.8.1) |

Either the rule should read "no sequence, gate clause or §12.1 entry", or the sequences should grow the calls. This
is a design decision; W13 copies the sequences as they are.
