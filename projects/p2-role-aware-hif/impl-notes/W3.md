# W3: `record/`

Step W3 of the [Implementation plan](../DESIGN.md#implementation-plan). It ports `khg_synth.py` into
`src/khg_contracts/record/` with the typed API of §10.2. Where DESIGN.md was ambiguous, the decisions below
follow `design-examples/` and the synthesis prototype. Nothing in DESIGN.md, `design-examples/` or `research/` was
edited, and no file of an earlier step was changed.

## Decisions

### API shape

- **`write_container(container, path, *, format=None)`.** §10.2 writes `format="jsonl" | "json"`. The default is
  the suffix: `.json` gives JSON, anything else JSONL, so writing `x.khg.json` does not put JSONL into a `.json`
  file. An explicit `format` wins. The write is atomic (a temporary file, then `os.replace`), and nothing is
  written when V or C fails.
- **The `.khg.json` layout** is not specified. `serialize(..., format="json")` writes the canonical container as
  `{"header": <canonical JSON>, "records": [` then one canonical record per line, then `]}`. It is deterministic,
  diffs by record, and each record line equals its JSONL line. The design-example files use insertion-ordered keys
  with `", "` separators; they are packaged data, not written by this function.
- **`normalize(record, schema=None)`.** The canonical form does not depend on the schema, so the parameter is
  optional. `normalize` never raises on bad content ("no checks"): whatever it cannot normalise is kept as written,
  so `validate_record` reports it afterwards (the P3a sequence).
- **`derive`** returns `{}` for an entity and for a lifecycle record (neither has a derived block; the fixture's
  `m:sup-1` has none), `{n_bound, n_unbound}` for a goal. `arity` raises `ValueError` for a lifecycle record
  (§2.7: lifecycle records are excluded from arity). The accessors raise `ValueError` for a non-hyperedge.
- **Errors carry registered codes.** Invalid values raise `ValidationError` (a `ValueError`): C001 (not exactly one
  key), C002 (unknown value kind, special or datatype), C004 (literal structure, precision, calendar, decimals),
  C010 (a wrong JSON type for an id or bindings), C011 (an `as_of` instant), S001/S002 (through `Schema`), S006.
- **`window(lit)`** returns instants in the §2.1 grammar and accepts the literal or a value `{"literal": ...}`.
  `window_seconds` gives the integer seconds (JDN × 86400 + time of day), the unit `Bounds` uses.
- **`event_hash(content_key, evidence)`** takes the content key first, as the prototype. `stamp_event_hashes`
  returns a copy and never replaces a stored hash (what `make_candidate` needs).
- **`iter_jsonl`** checks layer J only (V001 is the store's `load`, §6.2); findings are at `/lines/<n>` as in
  `jsonio.loads_lines`, and blank lines are the ones `loads_lines` skips.

### Semantics

- **Supports are sorted as strings** (code-point order, so `b10` sorts before `b2`), and evidence by id, as the
  prototype does; the stored digests depend on it. The default is every bid, the rule for `put` and event records.
  The `end_validity` and `transition` defaults of §2.8.1 belong to the store's events (W8).
- **A time literal gets `calendar: "gregorian"` only when its written year is 1583 or later.** Earlier years must
  state it (S006); `normalize` does not invent one.
- **An integral float precision is its integer** (`11.0` is `11`), as canonical JSON and the C layer's
  `"type": "integer"` read it (F10). The prototype refused it with C004. NaN, infinities and bools are C004.
- **Digits are ASCII.** The prototype's `\d` also matched other Unicode digits; the time and instant grammars use
  `[0-9]`, as the record schema does.
- **Refinement matching** uses augmenting paths (polynomial) instead of the prototype's backtracking; the results
  are the same.
- **`hyper_relational`** requires exactly one subject and one object binding (`ValueError` otherwise); the prototype
  took the first. `positional` refuses lifecycle and goal records (§2.10); `hyper_relational` and
  `role_value_set` refuse only what has no id (an unbound value; no `primary`), as the prototype.
- **The RDF projection** also writes `rdf:type khg:Hyperedge` per fact and `khg:valueKind` beside `khg:value`. §2.10
  does not list them, but the 329 triples of the plan include them, and `valueKind` is what makes an entity value
  and a fact value decodable. `khg:position` is written as the RFC 8785 number.
- **`iunreserved` is RFC 3987's**: ASCII unreserved plus the `ucschar` ranges. The prototype treated every non-ASCII
  character as unreserved. The two agree on the fixture; C1 controls, private-use characters and noncharacters are
  now percent-encoded. Decoding is unchanged, and the mapping stays reversible.
- **`render_text` labels**, as the prototype: `labels` first (so a relation or role id there is used), then the
  relation's schema `label` or the usage's local `label`, then the id. The global role vocabulary's labels are not
  used, so `point_in_time` renders as `point_in_time`, as the fixture expects.
- **`resolve_redirects`** accepts `{id: entity}` or an iterable of entity records. A redirect cycle (invalid data)
  stops at the first entity met twice, as the prototype.
- **Time roles holding a non-literal, non-special value** (an unbound slot of a goal) read like an absent start or
  a `somevalue` end, as the prototype.

- `_structure.py` is a small closed-resolver jsonschema runner for the one self-contained record schema, as W2's
  meta-schema runner is. W4's `validate/engines.py` is the general runner and may replace it; `jsonschema` is
  imported only when `write_container` runs, so importing `record` loads no validation engine (a test checks it).
- §10.1 also lists lifecycle and keys under `record/`. W5 adds those modules and their exports; the pure
  computations they need are here.
