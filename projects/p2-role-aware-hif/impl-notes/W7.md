# W7: `loaders/` and the G1 gate

Step W7 of the [Implementation plan](../DESIGN.md#implementation-plan): `Bundle`, `Context`, construction through
public constructors (F1), reconcile, the strict export rule and `ExportReport`, `derive` and `label`, and
deterministic output. It closes **G1**. It ports `research/designs/work-synthesis/khg_loaders.py` and turns
`g1_chain.py`, `native_ops.py`, `r03_cases.py` and `run_evidence.py` into tests. Where DESIGN.md was ambiguous, the
decisions below follow `design-examples/` and the synthesis prototype. Nothing in DESIGN.md, `design-examples/` or
`research/` was edited, and no file of another step was changed.

## Decisions

### Errors

- **A refused input raises `LoaderError`, which is also a `ValidationError`** (`_input.InputRefused`, a subclass of
  both). §10.2 names `LoaderError` for `loaders.*`; the refusals of the `validate=` modes carry validator codes (J, V,
  H, R, P), which the rest of the package raises as `ValidationError`. The subclass satisfies both readings.
  `info["findings"]` holds the findings with their paths (D001 at `/nodes/<j>/node`, P007 at `/network-type`, P010 at
  `/incidences/<i>`, as the decoder reports them). A path's J errors (strict parse) are refused the same way.
- **A strict export raises a plain `LoaderError` (P005)** with `info["report"]`. `bundle.report` is set before the
  raise, so the report of a refused export can be read too (the prototype left the previous report).
- **The order of the checks** is the prototype's: the `validate=` mode first, then D001, P007 and P010. In profile mode
  layer P already refuses `asc` and a missing direction, with the same codes.

### Loading

- **`validate="none"` still refuses a document without the HIF structure** (not an object, no `incidences` list,
  records without ids, ids that are not strings or integers, extra keys, a direction outside head and tail): the
  loaders cannot map it. The codes are layer H's (H001-H009), computed only when the cheap structural guard fails. No
  other layer runs.
- **A profile file** is one validated with `validate="profile"`, or one that declares `khg-profile` and has a
  well-formed `khg-bid` (`b1`, `b2`, ...) on every incidence, unique within its edge. Such a file keys its records by
  bid and exports in the §4.2 order in every mode; a declared profile with malformed bids is read as a file without
  the profile (keyed by ordinal, source order); the prototype keyed any declaring file by bid and failed with a
  `KeyError` on a missing one.
- **HyperNetX always gets a direction column** (None where a record has no direction), so `label` can set a new cell's
  direction in a file whose records have none; without the column HyperNetX would put it into `misc_properties`, an
  attribute. Exports are unchanged: a missing value is never written.
- **`load_hnx` refuses an incidence `attrs` key `khg-extra-incidences`** (P014, "unknown `khg-*` incidence attrs key")
  in every mode, since the loader reserves it; profile files already fail P014 in layer P. XGI carries the key as an
  ordinary attribute.

### Export

- **Files without the profile, HyperNetX:** the k-th record of a loaded (edge, node) pair's cell is that pair's k-th
  loaded record. A loaded record no cell carries is stale (its edge survives) or dropped (its edge was removed whole),
  as for XGI and for profile files; the prototype never reported them for HyperNetX. A second cell for one pair (which
  a HyperNetX rename onto an existing node can create) is treated as new. Without a `khg-bid` a rename cannot be told
  from a removal plus an addition, so in these files it is a partial fact plus a new record.
- **Injectivity** is judged on the node map of every carried loaded record, moved or not. The prototype looked at
  moved records only, so a rename onto an existing node (`ex:HeLa` -> `ex:TP53`) passed as injective there; here it is
  a `moved_conflict` and a strict export raises. A record that repeats a `khg-bid` another cell carries is a
  `moved_conflict` too and is not exported.
- **Report entries have one shape per class** in both libraries: `stale` and `dropped_records` hold full records,
  `unlabelled` memberships `{edge, node, direction?}` (the prototype gave HyperNetX cell records with their attrs),
  `moved` and `moved_conflict` `{edge, bid, from, to}` (the prototype mixed records into `moved_conflict`), and the
  dropped classes ids. `moved_conflict` has no duplicate entries.
- **Faithfulness beyond the prototype**, which only changes foreign files: `nodes` and `edges` keys absent from the
  loaded file stay absent when nothing is declared; a declared node or edge with `attrs: {}` keeps it (the context
  records which declarations had `attrs`); a loaded empty edge that no longer exists is reported in `dropped_edges`,
  as a vanished isolated node is in `dropped_nodes`. All 22 exact R03 cases are therefore also canonically exact,
  where the prototype compared node and edge records as multisets.
- **Order of new records** in files without the profile: after the loaded ones, sorted by the typed key (edge, node,
  direction, canonical attrs), for XGI labels too (the prototype kept XGI labels in call order). New node and edge
  ids follow the declared ones sorted by (type name, value); the prototype sorted by `str(value)`, which puts `10`
  before `9`.
- **HyperNetX edges** are exported from the edge property store when they are live or were empty in the loaded file,
  as in the prototype, so an edge the user removed is not reported as dropped (XGI removes it outright). Nodes come
  from the node property store; ones left without an incidence are reported.

### `Bundle`

- **`records` for XGI lists the records of live memberships** (the prototype returned every context record of the
  edge, stale ones included), so `roles` answers for the graph as it is now; the export report lists stale records.
  For HyperNetX it lists the records the cells carry, in cell order, with the export's weight reconciliation.
- **`derive` copies the labels** (the prototype shared the context, so labelling a derived bundle changed the original)
  and checks that the object comes from the bundle's library.
- **`label` checks its record** with registered codes: P005 for a missing or empty role, a missing or malformed
  `khg-bid` in a profile file, or a membership that does not exist (the prototype's code for a missing cell); P016
  for a bid another live record of the edge has; P010 for a `DiHypergraph` membership named without direction; H005,
  R004 and H009 for a bad direction, position, weight or extensions. HyperNetX writes a new cell's direction and
  weight into its columns (the prototype ignored both).

### Test data

- **R03's case files are copied into `tests/loaders/r03-cases/`** (27 from `research/probes/lib-cases/`, and c00 from
  the knowledge base's `schemas/sample.hif.json`, verbatim) so the tests read nothing under `research/` and run from
  the sdist, which carries `tests/`.
- **The evidence file is written to `tests/evidence/library-hif-evidence.json`**, where W0's examples mirror expects
  it; it is byte-identical to `design-examples/library-hif-evidence.json`, so `tests/packaging/test_examples.py` now
  compares all 151 files. The integrator should commit it with the step.
- **G1 assertion 3** asserts canonical equality of the containers and calls `store.compare_containers` (W8). While W8's
  function was missing the second test skipped; at the end of this step it was present and passes.

## Deviations from DESIGN.md

- `load_xgi` and `load_hnx` raise a `LoaderError` that is also a `ValidationError` for refused input (§10.2 names
  `LoaderError` only); see "Errors".
- `load_hnx` also refuses the reserved key `khg-extra-incidences` in incidence attrs (P014); §5's list of refusals
  does not name it.
- `validate="none"` refuses documents without the HIF structure with layer H's codes; §5 says it "runs nothing".
- Additions to §5's surface: `Bundle.lib`, and the names `EXTRA`, `HNX_KEYWORDS`, `REPORT_KEYS`, `VALIDATE_MODES`
  and `LoaderError` in `loaders.__all__`. Nothing in §5 or §10.2 was renamed or dropped.

## Observations (no change made)

- **HyperNetX's `rename` also loses the isolated `ex:Mazarin`**, as `clone()` and `sum()` do: the export reports it in
  `dropped_nodes`. The §5 table mentions only the moved record for `rename`, and `native-ops.json` records the same
  report (`moved: 1, dropped_nodes: 1`). It belongs in the HyperNetX issue's list next to `clone()` and `sum()` (§12.4).
- HyperNetX's `to_hif` emits a pandas `FutureWarning` (`fillna` downcasting); the evidence test filters it.
