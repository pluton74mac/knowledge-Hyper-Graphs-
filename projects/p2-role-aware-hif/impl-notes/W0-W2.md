# W0 to W2: package scaffold, `jsonio`, `schema/`

Steps W0, W1 and W2 of the [Implementation plan](../DESIGN.md#implementation-plan). Where DESIGN.md was ambiguous,
the decision below follows `design-examples/` and the synthesis prototype. Nothing in DESIGN.md, `design-examples/` or
`research/` was edited.

khg_contracts.examples out --tests tests` reproduces 150 of the 151 files of `design-examples/` byte for byte; the
151st is written by W7 (below).

## Decisions

### Codes

- Codes carry the registry's prefix: `KHG-J001`, not the `J001` of the prose. `error-codes.json` and the prototypes
  use the prefix.
- A test scans the package source and fails on any `KHG-` code that is neither registered nor planned.

### W1 `jsonio`

- **J004 also covers a number that overflows to infinity** (`1e400`). The prototype accepted it as `inf` and only
  `canonical` refused it later, with the same code.
- **`canonical` refuses an integer outside ±(2^53−1) with J006** rather than printing it. RFC 8785 would print the
  rounded double, which is not the stored value. Layer J already keeps such integers out of parsed documents.
- **Key order is by code point**, as §2.1 and the prototype say. RFC 8785 orders by UTF-16 code units; the two differ
  only between astral-plane keys and keys in U+E000–U+FFFF. A test pins the §2.1 order.
- Keys that are equal after NFC raise S020 in `canonical`, as in the prototype. A lone surrogate reaching `digest`
  raises J005.
- **JSONL splits on `\n` only** (a trailing `\r` is dropped). The prototype used `str.splitlines()`, which also
  splits on U+2028, U+0085 and others that may appear raw inside a JSON string. Blank lines are skipped, as in the
  prototype, and a J finding on a line has the path `/lines/<n>`, n counting non-blank lines: the addressing of the
  queue and C4 patches.
- Added beside the §10.2 names: `loads_lines`/`load_lines` (JSONL), `number` (the RFC 8785 number form) and
  `hexdigest` (the digest without its prefix, for the truncated derived-node ids of §4.2).

### W2 `schema/`

- **The meta-schema is new** (`khg-relation-schema-1.0.0.schema.json`, generated by `schema/codegen.py`). It follows
  §3 field for field and the conventions of §8.1: `x-khg-code` on every constraint (M015 by default; M001 for a
  relation without roles, M004 for the version, M006 for the datatype, M007 for the time model and time usages, M012
  for `primary`, M014 for `complete`), absolute `$ref`s, and if/then/else instead of `oneOf`/`anyOf`.
- **What the meta-schema requires.** `kind`, `format`, `id`, `version`, `roles` and `relations` at the top; `role`,
  `slot`, `fillers`, `min` and `max` on a usage; `type`, `roles` (two or more) and `severity` on a constraint; `roles`
  on a key, whose `temporal` defaults to false and `on_collision` to `dispute` (§2.5). No other fields are accepted
  (M015). Entity types take `id` and `parents` only, as §3 lists them.
- **Python checks** are the prototype's `m_checks` without the parts the meta-schema now covers, so no single fault is
  reported by both halves. Of the 19 M cases each gives exactly the codes the list records, under both engines, and
  fastjsonschema's single code is always among jsonschema's (single-fault containment).
- **Checks added beyond the prototype**, each under an existing code and none firing on a case or a base: M015 for a
  constraint role the relation does not use, `units` on a non-quantity filler, `precision_min` on a non-time filler, a
  declared scale named `probability`, a duplicate scale and a scale whose `min` is not below its `max`; M012 when
  `subject` equals `object`; M007 when the time model's start and end are one role.
- **A time bound is "a time usage with max 1 and one time-literal filler"**, as §3 words it. The prototype required
  the filler list to equal `[{"literal": "time"}]`, which refused a `precision_min` on a time bound.
- **`Schema`** exposes `id`, `version`, `ref` and `sha256` as properties, as §10.2 lists them (the prototype used
  methods). `relation()` and `usage()` raise `ValidationError` with S001 or S002. `key()` returns the key with its
  defaults filled. `usages()` includes the built-in `khg:end_cause` meta usage on interval relations, as the prototype
  did.
- **`load_schema`** runs J (for a path), then V (`format` must be `khg-relation-schema/1.0.x`; V001 stops the run),
  then M. It also accepts a `Schema` and returns it unchanged. `check_schema(doc, engine=...)` returns the findings
  without raising.
- **`schema_hypergraph`** keeps the schema's relation order, so the GYO residue comes out in the order §3 states. With
  `"meta"` in `slots`, the built-in `khg:end_cause` usage appears on the interval relations.
- **The meta-schema runner** in `schema/checks.py` is a small closed-resolver runner for the one self-contained
  meta-schema, for both engines. W4's `validate/engines.py` is the general runner and may replace it.

### W0 scaffold

- **`data/` is a regular package** (`__init__.py`, `__main__.py`), so `importlib.resources` works the same on 3.10.
  `khg_contracts.data` reads files (`load_json`, `load_jsonl`), checks the vendored HIF schema against its pinned hash
  (`hif_schema()`), lists every packaged schema by `$id` for the engines (`schema_documents()`), and verifies the
  manifest.
- **`data/manifest.json` is new.** It pins the sha256 of every packaged data file. `verify()` reports missing,
  changed or unlisted files, and CI's wheel job runs `python -m khg_contracts.data --check` for the package-data
  hashes. A step that adds or changes a packaged file regenerates it with
  `python -m khg_contracts.data > src/khg_contracts/data/manifest.json`.
- **The queue schema is not seeded.** §10.1 lists `khg-queue-1.0.0`, but the plan gives it to W9. W9 adds it to
  `data/schemas/` (the generator's helpers `X`, `iff`, `propagate`, `absolutise` and `render` are importable from
  `schema/codegen.py`) and regenerates the manifest. The examples mirror ignores it, since `design-examples/schemas/`
  has four files.
- **`examples.py`** maps packaged files to `design-examples/` paths with a fixed rule: `fixture/` and `sample/` to the
  top level, `scenarios/` to `conformance-scenarios/`, the four mirrored schemas to `schemas/`. With `--tests DIR` it
  also copies the five test-only files from a checkout's `tests/`. CI's examples job runs it with `--tests tests`, then
  `diff -r`.
- **`library-hif-evidence.json` is expected at `tests/evidence/library-hif-evidence.json`**, written by W7's
  evidence test (§10.5). Until W7 lands, the examples CI job reports it missing; the byte-equality test tolerates
  that one file only.
- **The four other test-only files** are copied from `design-examples/` to `tests/gate/golden-sha256.json`,
  `tests/loaders/native-ops.json`, `tests/loaders/r03-loader-cases.json` and `tests/scorers/r05.relation-schema.json`.
- **`pyproject.toml`.** The version is `1.0.0.dev0`, read by hatchling from `__init__.py`. It needs
  `hatchling>=1.27` for the PEP 639 `license-files`. It has no `readme`: the root README describes the knowledge base,
  and W14 decides the package description. The sdist holds `src/`, `tests/`, `LICENSE` and `pyproject.toml`, not the
  knowledge base.
- **pytest runs with `--import-mode=importlib` and `--strict-markers`**, so test files in different directories may
  share a basename without `__init__.py` files. The markers `gate`, `libs` and `evidence` are registered in
  `conftest.py`.
- **The network block** replaces `connect`, `connect_ex`, `sendto` and `sendmsg` on `socket.socket` for non-AF_UNIX
  sockets, and name resolution and `create_connection`. It raises an `OSError` subclass, so code that tolerates being
  offline behaves as offline. Local AF_UNIX sockets still work.
- **`__init__.py`** imports subpackages on first attribute access (PEP 562) through `find_spec`, so later steps never
  edit it. The import-hygiene test imports every module of the package in a child process, so it also enforces the
  lazy-import rule on later steps.
- **`CONTRACTS`** is a read-only mapping of the §11.1 format ids and the ten hash domains (`"1"` for
  `khg-render` and the domains).
- **Errors.** `ValidationError` and `LoaderError` are also `ValueError`s, and `NotFound` is a `LookupError`.
  `.code` gives the first code. `ValidationError.from_findings` builds `codes` from the error findings, in first-seen
  order. `errors.make_finding` gives the §8.1 finding shape.
- **`cli.py` is a placeholder** so the four console scripts install. Each exits with 2 and "not implemented yet".
  W12 owns the file; the entry points are `validate_main`, `convert_main`, `migrate_main` and `conformance_main`.
